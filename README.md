# 安全无线控制系统：PC–ESP32–FPGA–STM32端到端实现

本仓库记录第十届全国大学生集成电路创新创业大赛 Robei 企业命题作品“面向 IoT 边缘节点的 GALS 异步安全加速网关设计”的脱敏工程资料。作品获华中分赛区二等奖。

项目以四轮小车作为真实执行载体，将网络接入、密码事务处理和物理控制分配到不同节点，形成由 PC 控制端、ESP32、Artix-7 FPGA 和 STM32 组成的双向闭环系统。仓库的用途是保存可公开的系统架构、硬件平台、设计决策和验证结果，不发布密钥、网络凭据、完整固件、bitstream 或未脱敏日志。

> **关于 GALS 名称**：GALS 是参赛作品的正式命题名称。本公开仓库主要记录端到端控制系统、密码事务集成和分层验证结果，不展开完整时钟域划分、CDC 结构和未脱敏 RTL 细节，因此不以本仓库内容单独证明完整 GALS 实现。

## 系统架构

![系统架构](architecture.svg)

正向链路用于传递控制请求：

`PC控制端 → Wi-Fi/UDP → ESP32 → UART → FPGA → UART → STM32 → 电机`

返回链路由 STM32 生成设备状态，FPGA完成状态校验和响应处理，经 ESP32 返回 PC。PC 仅在来源、帧结构、操作码、解密、CRC 和序列号检查通过后更新已确认状态。

当前 `architecture.svg` 是面向公开展示的详细架构图；[`architecture.mmd`](architecture.mmd) 是便于后续编辑的 Mermaid 简化架构源文件，两者表达同一系统关系，但并非逐元素一一对应。

## 硬件平台

![硬件平台概览](docs/images/hardware-overview.jpg)

- **FPGA处理节点**：Robei Artix-7 开发板，器件为 Xilinx XC7A50T；
- **无线通信节点**：ESP32-WROOM 开发板；
- **设备控制节点**：STM32F103 控制板；
- **执行与供电**：四轮移动底盘、电机驱动与独立电源模块。

硬件照片、接口角色和供电说明见 [硬件平台说明](docs/hardware.md)。

## 模块职责

### PC控制端

- 构造控制请求并发起 UDP 通信；
- 执行请求侧的加密和帧封装；
- 接收、解密并校验返回帧；
- 只有在完整校验通过后更新设备状态，避免将发送命令误当作实际执行结果。

### ESP32通信节点

- 建立 Wi-Fi 连接并完成 UDP 双向收发；
- 在网络数据报与 FPGA UART 数据流之间进行透明桥接；
- 不解释车控业务语义，减少通信层与安全事务层之间的耦合。

### FPGA安全事务节点

- 接收并解析来自 ESP32 的串口帧；
- 调用 AES/SM4 参考核心完成密码处理；
- 完成操作码、CRC、序列号和事务状态检查；
- 将通过验证的控制请求转换为 STM32 控制帧；
- 校验 STM32 返回的状态，并生成加密响应返回 PC。

### STM32执行节点

- 解析 FPGA 下发的控制帧；
- 通过 PWM 和 GPIO 驱动电机；
- 生成真实设备状态并返回 FPGA；
- 在通信超时或链路失联时执行安全停车，最终将 PWM 置零。

## 主要工程工作

- 完成四节点系统的需求拆解、模块边界和接口协议设计；
- 完成 PC、ESP32、FPGA、STM32 之间的双向通信链路集成；
- 完成 ESP32 Wi-Fi/UDP 与 UART 桥接的配置、开发和实物调试；
- 完成 STM32 控制帧解析、电机驱动、状态生成和失联停车机制；
- 基于公开 AES/SM4 参考核心完成 FPGA 接口适配、事务控制和车控链路集成；
- 建立软件、RTL、综合实现和真实硬件分层验证流程；
- 维护 Git 提交、固件与 bitstream 哈希、构建报告和测试日志，区分不同版本和证据层级。

## 关键设计决策

系统设计强调职责分层，而不是把全部功能堆叠到单一设备：

1. ESP32只承担网络接入和透明桥接，避免通信固件成为业务状态的第二来源；
2. FPGA负责密码事务、帧校验和控制事务，保证安全检查位于执行链路之前；
3. STM32负责最终物理执行和失联停车，使安全停车不依赖 PC、Wi-Fi 或 FPGA继续工作；
4. 状态回传以 STM32生成的实际状态为起点，PC不使用“已发送命令”冒充“已执行状态”。

详细说明见 [关键设计决策](docs/design-decisions.md)。

## 验证方法

项目采用分层验证，避免用单一类型的测试替代完整系统证据：

- **软件层**：协议、密码调用、状态过滤和异常路径回归；
- **FPGA层**：pytest、RTL仿真和综合后通信验证；
- **实现层**：器件、时序、DRC和约束检查；
- **硬件层**：STM32直接控制、完整链路失联停车和负向异常注入。

当前公开摘要包括：Python 回归 907 passed、1 skipped；FPGA pytest 73 passed；RTL与综合后 UART 入口到出口 no-force 测试均为 10/10；实现器件为 `xc7a50tfgg484-1`，WNS 0.536 ns、WHS 0.006 ns。较早的资格产物还完成了 AES/SM4 STOP 压力、STM32 静默停车和完整链路失联停车测试。

详细解释见 [验证方法与证据层级](docs/verification.md)，公开结果见 [验证结果摘要](EVIDENCE.md)，稳定编号见 [公开证据索引](docs/evidence-index.md)。

## 项目边界

- AES/SM4密码核心来自公开参考实现；项目贡献集中在接口适配、事务控制、系统集成、故障定位和验证，不声明从零设计密码算法核心；
- 离线软件测试、RTL/综合验证和真实硬件资格测试属于不同证据层，不能互相替代；
- 比赛后期存在 AES 精简配置，不能与完整 AES/SM4 开发基线描述为同一个 bitstream；
- 超声波实体未安装，只完成接口、冻结向量和软件/RTL模拟验证，不声明真实距离测量通过；
- 本仓库经过脱敏处理，不包含真实密钥、Wi-Fi凭据、授权令牌、完整固件、bitstream和未处理原始日志。
