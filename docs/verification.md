# Verification Notes

本项目的验证材料按证据层级组织。各层回答的问题不同，不能用其中一层替代另一层。

## 1. 软件回归

公开摘要记录：

- Python回归：907 passed，1 skipped。

该层主要覆盖协议处理、密码调用封装、帧校验、状态过滤和异常路径。它能够证明软件逻辑在既定输入下符合预期，但不能单独证明RTL、综合后网表或真实硬件行为。

## 2. FPGA测试与RTL验证

公开摘要记录：

- FPGA pytest：73 passed；
- RTL UART入口到UART出口 no-force：10/10。

该层用于验证FPGA侧接口、事务和串口数据通路。`no-force`表示测试不通过直接强制内部状态来绕过真实入口，而是从UART入口驱动请求并观察UART出口结果。

RTL仿真通过说明设计在仿真模型和测试条件下满足预期，但仍需要综合实现和板级验证。

## 3. 综合实现与时序

公开摘要记录：

- 综合后UART入口到UART出口 no-force：10/10；
- Vivado 2024.1实现器件：`xc7a50tfgg484-1`；
- WNS 0.536 ns；
- WHS 0.006 ns；
- 无black box、NSTD、UCIO、critical warning或DRC error。

该层用于检查RTL经过综合和实现后，通信路径及关键逻辑没有因优化、约束或网表变化而失效，同时确认实现满足报告中的时序和DRC要求。

综合后测试和时序通过仍不能替代真实板卡上的电气、供电、串口接线和执行器测试。

较早资格产物的公开摘要记录：

- AES正式STOP压力：600次通过；
- SM4正式STOP压力：600次通过；
- STM32直连命令静默停车：10/10；
- 完整PC–ESP32–FPGA–STM32链路失联停车：10/10；

## 5. 版本与证据边界

### 完整开发基线

完整开发基线包含AES/SM4双向事务、软件回归、FPGA测试、RTL验证、综合后验证和实现报告。相关结果用于说明系统设计和开发状态。

### 较早资格产物

真实硬件压力和负向注入证据来自较早的资格产物。其结果可证明对应版本在指定测试中的表现，但不能自动外推到后续所有bitstream。

### 比赛现场精简配置

比赛后期另有AES精简配置。它与完整AES/SM4开发基线不是同一个bitstream，因此公开描述中必须保持版本区分。

### 未完成范围

超声波实体未安装。项目只完成相关接口、冻结向量以及软件/RTL模拟验证，不声明真实距离测量通过。

## 6. 证据记录方式

完整工程中使用以下信息建立可追溯性：

- Git commit SHA；
- STM32固件哈希；
- FPGA bitstream哈希；
- Vivado构建与实现报告；
- 软件/RTL测试日志；
- 真实硬件测试记录和异常注入结果。

公开仓库只保留脱敏摘要。完整源码、固件、bitstream、密钥和未处理日志不在本仓库发布。
